# 六、开发、打包与发布

本文是项目目录安排与开发规范的唯一维护位置。人类开发者和 AI 开始任务前，先从 README 了解项目，再阅读本文并检查相关模块。新增内容按下列职责归档；调整目录职责时同步更新本文。

## 一、项目目录与文件职责

下列清单覆盖当前源码工作区的全部根目录文件和文件夹，子目录只展开有长期意义的位置。源码、文档和构建配方纳入 Git；标注为本地生成的目录由相应工具按需创建，克隆后不要求全部存在。

```text
EtherCAT-Viewer/
├── README.md                     项目简介、快速开始和文档导航
├── THIRD-PARTY-NOTICES.md         第三方组件、许可及对应源码说明
├── .gitignore                    本地环境、运行数据和构建产物的忽略规则
├── launch.py                     应用启动、浏览器打开和退出入口
├── start-viewer.cmd              Windows 双击启动入口
├── start.ps1                     PowerShell 启动入口
├── requirements.txt              固定版本的运行依赖
├── build-windows.py              Windows 单文件构建脚本
├── EtherCAT-Viewer.spec           PyInstaller 打包配方
├── viewer/                       项目 Python 包
│   ├── configuration.py          逐项配置校验、依赖规划与字段合并
│   ├── settings.py               版本化配置、校验、迁移与原子保存

│   ├── system.py                 当前用户 Windows 登录启动
│   ├── bridge/                   中瑞兼容与扩展 TCP、配置和重采样
│   └── static/                   网页 HTML、CSS 和 JavaScript
│       ├── drafts.js             字段草稿、基线与冲突管理
│       ├── ui.js                 公共图标与通知
│       ├── images/modules/       随程序离线提供的官方产品缩略图
│       └── vendor/               随程序提供的第三方网页组件及其许可
├── tests/                        项目自动化测试
│   └── browser/                  可重复执行的浏览器 UI 回归场景

├── logs/                         本地生成：运行日志和调试原始数据
├── recordings/                   本地生成：程序录制的 CSV
├── build/                        本地生成：PyInstaller 构建中间文件
```

| 类别 | 路径 | 职责与版本管理要求 |
| --- | --- | --- |
| 项目代码 | `viewer/` | Python 后端、通信进程、硬件访问及诊断工具。新功能优先扩展现有模块，源码提交到 Git。模块分工见 [系统架构与实现细节](03-系统架构与实现细节.md)。 |
| 网页资源 | `viewer/static/` | HTML、CSS 和 JavaScript。第三方网页组件放在 `vendor/` 子目录并保留许可，随源码提交和打包。 |
| 自动化测试 | `tests/` | 可重复运行的项目测试，文件使用 `test_*.py` 命名，随对应功能提交。 |
| 项目说明 | `docs/`、`docs/images/` | 本项目的安装、操作、架构、诊断、验收、开发与协议桥接说明，以及长期使用的配图，提交到 Git。 |
| 外部参考 | `reference/` | 外部设备协议等长期参考资料，使用中文 Markdown 文件名，提交到 Git。临时回环接线和原始调试数据不作为长期协议依据存放于此。 |
| 第三方许可 | `licenses/`、`THIRD-PARTY-NOTICES.md` | 第三方许可文本、组件说明与对应源码信息，提交到 Git。新增或更新第三方组件时同步核对。 |
| 项目入口 | `README.md` | 项目简介、快速开始和文档导航，提交到 Git；细节链接到编号文档。 |
| 启动入口 | `start-viewer.cmd`、`start.ps1`、`launch.py` | 双击启动、PowerShell 启动和应用启动流程，提交到 Git。 |
| 依赖与构建 | `requirements.txt`、`build-windows.py`、`EtherCAT-Viewer.spec` | 运行依赖、构建脚本与打包配方，提交到 Git。 |
| Git 管理 | `.git/`、`.gitignore` | `.git/` 由 Git 自身维护，不作为项目文件提交或手工修改；`.gitignore` 纳入版本管理。 |
| 本地开发环境 | `.venv/`、`.pytest_cache/`、`__pycache__/` | 虚拟环境与自动生成缓存，已忽略，不提交。子目录内的 Python 缓存同样不提交。 |
| 临时工具 | `.tooling/` | 一次性调试脚本、下载、浏览器测试依赖和构建虚拟环境，已忽略，不提交。可维护的正式工具按职责迁入 `viewer/`，正式测试迁入 `tests/`。 |
| 运行数据 | `logs/`、`recordings/` | 日志、原始报文、测量数据、调试截图和 CSV，已忽略，不提交。程序录制放入 `recordings/`，其他诊断材料放入 `logs/`。 |
| 构建产物 | `build/`、`dist/` | 打包中间文件、EXE 和校验文件，已忽略，不提交；发行文件通过 GitHub Release 分发。 |

源码运行时，日志和录制分别写入项目目录下的 `logs/` 与 `recordings/`。EXE 运行时，相同类别的数据写入 `%LOCALAPPDATA%\EtherCAT-Viewer` 下对应的子目录。配置由源码与 EXE 共用 `%LOCALAPPDATA%\EtherCAT-Viewer\settings.json`，使用修订号、完整校验、原子替换和备份。运行日志位置与配置位置分别管理。公共运行路径通过 `viewer/paths.py` 处理，不依赖当前工作目录或某台开发电脑的绝对路径。

## 二、目录与文件新增规则

1. **先查现有位置。** 新建前查看本节目录表和相关模块，优先复用已有文件或目录。不得仅因个人或 AI 偏好，增加与现有职责重复的根目录，例如 `src/`、`backend/`、`frontend/`、`references/`、`temp/`。
2. **保持根目录稳定。** 功能细分优先在现有目录内部完成。确需新增根目录文件或文件夹时，先确认现有位置无法承载，在变更说明中解释必要性，并在同一次变更中更新本文的目录树和用途表。
3. **区分长期结论与临时材料。** 一次性探查脚本放入 `.tooling/`，原始报文和测量结果放入 `logs/`；确认后的本项目验收结论整理到 [现场现状与验收记录](05-现场现状与验收记录.md)，外部设备协议结论整理到 `reference/`。长期展示用的截图整理到 `docs/images/` 后再提交。
4. **保持文档单一来源。** 项目说明优先更新已有编号文档，README 保持导入用途。外部设备资料按设备或主题形成可独立使用的中文 Markdown，使用相对链接引用，不在 `docs/` 和 `reference/` 中复制维护同一份资料。新增编号文档时同步维护 README 导航和相关链接。
5. **不把生成目录当作源码位置。** 不在环境、缓存、日志或构建目录中维护必须随项目交付的代码。新类型的生成文件应复用已有生成目录；确需增加忽略规则组时，用中文注释说明用途，并核对没有误忽略源码。

常见新增任务按以下位置处理：

| 任务 | 保存位置 |
| --- | --- |
| 新增网页功能 | 网页代码放在 `viewer/static/`，配套接口或通信逻辑放在 `viewer/` 的对应模块。 |
| 整理外部设备协议 | 长期结论放在 `reference/设备或主题名称.md`，原始调试材料按临时材料规则归档。 |
| 临时实机调试 | 脚本放在 `.tooling/任务名/`，原始结果放在 `logs/任务名/`。 |
| 新增正式自动化测试 | 放在 `tests/test_功能名.py`，测试结果和临时输出不提交。 |
| 生成发行文件 | 中间文件放在 `build/`，EXE 和校验文件放在 `dist/`，通过 Release 分发。 |

## 三、开发规范

1. **编码与命名。** 文本文件使用 UTF-8。读取出现乱码时先纠正编码或读取方式并重新读取，确认内容完整后再修改。中文说明文档使用中文文件名，项目说明沿用两位数字编号；代码文件和标识符遵循现有语言及模块风格。保留既有文件的换行方式，不因格式偏好额外引入格式化工具或改写无关文件。
2. **程序职责。** 通信调度、波形生成和硬件操作归通信进程及相关模块；HTTP、WebSocket、会话和 CSV 服务归服务端；界面、图表和交互归静态网页。具体分工以 [系统架构与实现细节](03-系统架构与实现细节.md) 为准，新增功能沿用现有进程和数据流边界。
3. **路径、依赖与资源。** 公共运行路径复用 `viewer/paths.py`，避免写死开发电脑路径。新增或升级运行依赖时维护 `requirements.txt` 的固定版本；新增静态资源或第三方组件时核对打包配方、许可说明，以及源码与 EXE 两种运行方式。
4. **验证与输出保护。** 根据行为变化补充有意义的测试，验证关键边界和失败路径。涉及硬件输出、连接或退出流程的修改，应核对手动网卡选择、管理页面恢复、逐通道写入归属、人工清零优先级、服务租约、容错阈值、硬件策略和正常退出清理等相关保护，并记录实际验证范围。文档修改检查内容与链接；功能修改执行相应测试，发布前再完成本篇规定的验收。
5. **提交与协作。** 沿用 `work/任务名` 工作分支和 PR 流程，具体要求见本篇“六、分支与协作”。Git commit 使用 `<type>(<scope>): <description>`：type 使用标准英文，description 和正文使用中文，代码标识符及必要技术术语保留原文。实质性变更的正文说明主要改动、原因及必要的验证结果。
6. **提交前检查。** 检查 `git status --short` 和 `git diff`；暂存后再检查 `git diff --cached`，确认变更范围及目录归属。凭据、令牌、环境、安装包、原始运行数据和构建产物不提交；长期文档中的地址与测量结论注明适用环境，避免把某次临时接线当作通用配置。

## 四、开发和测试

使用 Windows 与 Python 3.12 x64。在项目目录执行以下命令。

```powershell
python.exe -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements.txt pytest
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
```

测试覆盖量程换算、PDO 结构、波形和周期校验、进程保护、网卡选择、控制台启动及桥接协议，并验证配置迁移、修订冲突、电气校准、工程量、同步与滤波回读、WKC 容错和逐通道保护。以实际测试输出为准，不用固定测试数量作为通过条件。桥接修改还须验证分帧、原版兼容、原始数据与补点区别、控制范围、慢客户端和清零路径；协议定义统一维护在第 07 篇，真实板卡协议保留在 reference/。测试实机前确认输出安全、匹配端子及设备身份。

浏览器回归维护在 `tests/browser/ui-regression.mjs`。在已取得管理权限的 EGO 页面导入后调用 `mixedCardCycles(page, 20)`、`periodDraftRegression(page)`、`fieldIsolationAndRetry(page)`、`twoPointPreviewRace(page)` 和 `refreshKeepsConnection(page, 3)`；它们使用普通 UI 操作，并核对实际请求与保存值，不创建生产模拟模式。周期回归需确认没有待测波形，并会将周期恢复为测试前值。开发中重新加载最新资源，避免浏览器内存缓存影响判断。执行前保持实机零值，停止相关虚拟卡；另行验证多页面、网络中断恢复、曲线缩放、窄窗口、CSV、告警及配置持久化。浏览器临时入口脚本和截图仍归 `.tooling/` 与 `logs/`。

独立长测会占用网卡。先从仪表盘断开实机，再查询网卡 GUID 并将示例值替换为目标接口。默认执行 180 秒，加载已保存的硬件设置，结果写入项目 `logs/zero-soak.json`。长测与 Web 服务不能同时占用同一接口。

```powershell
Get-NetAdapter -Physical | Format-Table Name, Status, LinkSpeed, InterfaceGuid
.\.venv\Scripts\python.exe -X utf8 -m viewer.soak --adapter-guid '{00000000-0000-0000-0000-000000000000}' --seconds 180
```

## 五、构建 Windows x64 单文件

```powershell
python.exe -X utf8 .\build-windows.py
```

脚本使用单独构建虚拟环境、运行时 wheel 和 PyInstaller 6.22.3。应用版本从 viewer/__init__.py 读取，构建脚本和打包配方使用同一版本。生成 `dist/EtherCAT-Viewer-v0.2.0-windows-x64.exe` 及其 `.sha256` 校验文件。构建配方打包本机 Python 运行时、PySOEM 扩展、Web 服务、网页和第三方许可。Npcap 由用户另行安装。使用 `multiprocessing.freeze_support()` 分流 Windows 子进程入口。只读资源从解包目录加载，运行数据存入 `%LOCALAPPDATA%\EtherCAT-Viewer`。

发布文件未做 Authenticode 签名，可比对 Release 的 SHA-256。第三方许可和 SOEM 对应源码见 [第三方组件与许可](../THIRD-PARTY-NOTICES.md)。[PyInstaller 多进程与单文件说明](https://pyinstaller.org/en/latest/common-issues-and-pitfalls.html)

## 六、分支与协作

1. 从最新的 `main` 创建 `work/任务名` 工作分支，在该分支提交，并推送到 GitHub。需要补改时，把新提交推到同一工作分支。
2. 从工作分支向目标分支创建 Pull Request（PR）。`main`、`release/` 下的分支及其他受保护分支，常规合并需由另一位有写权限的协作者批准。PR 推送新的可审核改动后，原批准失效。
3. 受保护分支对普通协作者禁用直接推送和强制推送。仓库管理员的例外为 GitHub Rulesets 的 **Always allow**，实际绕过可在仓库 **Settings → Rules → Insights** 查看。

## 七、发布前验收

1. 把 EXE 单独放进含中文和空格的目录，测试可见控制台、默认浏览器选项、O 键、最小化、六个功能页、动态通道、网卡恢复、进程退出和端口竞争。
2. 以零输出连接实机，验证 OP 和 WKC，记录 10 ms 档三分钟统计；DC 单独记录周期、主机相位与模块同步报警，不能以配置成功代替同步稳定验收。做小幅回环、TCP、CSV、配置共用、清零确认、Ctrl+C 和关窗。
3. 填写 [现场现状与验收记录](05-现场现状与验收记录.md)，列出测试环境和未验证项。在受控目录生成校验文件，确认仓库差异与产物均来自拟发布的同一版本。

## 八、GitHub Release

将发行改动通过 PR 合入 `main` 后，快进同步本地 `main`，核对待发布的提交并在该提交上打新版本标签。用本地 GitHub CLI 上传 EXE 和 SHA-256，发行说明用中文。可先建草稿核对资产，再正式发布。以下以 `v0.2.0` 为版本号示例。

```powershell
git switch main
git pull --ff-only origin main
git tag -a v0.2.0 -m "EtherCAT Viewer v0.2.0"
git push origin refs/tags/v0.2.0
gh release create v0.2.0 --verify-tag --draft --title "EtherCAT Viewer v0.2.0" --notes-file <发行说明文件> <EXE路径> <校验文件路径>
gh release edit v0.2.0 --draft=false --latest
gh release view v0.2.0 --json url,tagName,isDraft,isPrerelease,assets
```

命令中的尖括号占位符替换为实际路径，含空格的路径加引号。发布后下载两项资产，在本地比对 `Get-FileHash -Algorithm SHA256`，并核对标签、默认分支和 [Releases](https://github.com/llbk-kevin/EtherCAT-Viewer/releases)。[GitHub CLI 发布命令](https://cli.github.com/manual/gh_release_create)
