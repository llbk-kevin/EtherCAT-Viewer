# 四、通信诊断与故障排查

## 一、先读懂状态与回执

OP 表示从站进入运行状态，可以进行正常过程数据交换。PREOP 用于参数配置，SAFEOP 表示安全运行阶段；页面显示中文名称，详细 AL 错误码保存在诊断包。

WKC（Working Counter）是从站处理本轮读写的计数回执。当前台架 3/3 表示与实际 PDO 映射的预期一致，其他拓扑预期可能不同。1/3 是部分处理回执，−1/3 表示主站未收到本轮有效帧。一次 −1 可能与接收超时、调度、驱动或链路有关，单靠它不能定位网线或模块。WKC 正常也不代表端子电压已被独立测量。

主界面按通道显示欠量程、超量程、同步错误、数据无效等状态，不显示原始 PDO 十六进制。通道报警与总线掉线是不同事件；一个 AI 无效不会因此关闭整条总线或其他不受影响的卡。关键名词旁的 i 可悬停、聚焦或点击查看说明。

## 二、周期、抖动和真实采样

| 指标 | 含义 |
| --- | --- |
| 目标周期 | 主站希望多久交换一次 PDO，默认 10 ms，可设 1–50 ms |
| 实际周期间隔 | 相邻两次真实发送起始时刻的差 |
| 周期偏差/抖动 | 实际间隔减目标周期，可为正或负 |
| 收发耗时 | 单轮主站发送至接收返回，独立于完整周期 |
| 实际更新率 | 按实际 PDO 间隔计算，不是网页刷新率 |
| P95 | 约 95% 的有效样本不超过此数；另看最大值了解尖峰 |
| 调度漏期 | 来不及运行而跳过的调度槽，不是网络丢帧 |
| 原始源遗漏 | 通信进程到桥接的数据队列缺口，会影响采集完整性 |
| 网页推送遗漏 | 网页队列或显示未消费的样本，单独统计，不等于 EtherCAT 掉包 |
| 逻辑采样率/补点 | TCP 按请求节拍重复有效前值，不能增加独立测量细节 |

诊断页保留最近 30 分钟逐周期历史，按本机时间绘制四张时间线：实际间隔、目标偏差、收发耗时与 WKC。滚轮缩放、框选和回到实时可对照电脑操作；长时间窗保留峰谷和断点。数字统计最近 10 秒。DC 的时钟同步不消除 Windows 主机发包抖动，1 ms 仍需按实测判断。DC 模式还要看模块同步错误与丢事件计数：WKC 正常和从站保持 OP，不足以证明同步长期稳定。当前 Windows 实测仍有同步报警，默认使用 SM 帧同步，详见第 05 篇。[EL3104 工作模式](https://infosys.beckhoff.com/content/1033/el31xx/1803816843.html)

## 三、容错、故障策略和自动恢复

默认连续 10 次 WKC 异常或异常持续 500 ms，任一达到即进入故障处理。容错期间冻结最后确认目标、暂停采集发送，保留 TCP 连接；恢复后继续任务，不补发缺口期间的旧输入。明确的链路断开、从站退出 OP、工作进程异常不等待此阈值。

硬件看门狗默认 600 ms，保存时校验不小于容错时间＋max(50 ms,两个通信周期)。每个真实 AO 分别配置总线、网页、TCP 控制端失联动作：归零、保持、指定电压；网页还可选后台继续任务，默认如此。网页等待时间默认 5 秒，只对需要失联处理的策略有意义。设置保存后下次自动沿用。

总线“保持”同时写入并回读 EL4134 硬件看门狗模式；即使 PC 无法再发送，模块也按已确认策略动作。保持的末值是最后接收的输出，程序失去通信时不能确认其实际电压。模块仍需供电；断电后的行为不属于保持保证。正常退出、人工清零、扩展显式释放继续请求物理零目标。[EL41xx 看门狗](https://download.beckhoff.com/download/document/io/ethercat-terminals/el41xxen.pdf)

超限时停止旧波形、撤销写入租约，自动重连按 1/2/5/10/30 秒退避。重新核对拓扑、配置和零输出并稳定后，恢复监听、等待新指令；不重放旧任务。TCP 自动重新接管可逐卡保存；人工“全部清零并锁定”停止发布，不会被该选项自动解除。手动断开取消连接意图。

## 四、日志如何分类与定位

事件统一在诊断页筛选，其他页面显示相关摘要：

| 分类 | 内容 |
| --- | --- |
| 连接失败与恢复 | 网卡不可用、无从站、身份不匹配、参数回读失败、进入 OP 与重连 |
| 运行与通信异常 | WKC、退出 OP、队列或进程异常、故障策略及前后片段 |
| 通道报警 | 欠量程、超量程、同步错误、无效及恢复 |
| 控制与配置 | 连接/断开、授权、清零、保存、虚拟卡和客户端操作 |

默认日志保留 30 天且总量不超过 200 MiB，10 MiB 轮转。记录 JSONL，包含墙上时间与单调时间、会话、WKC、周期、收发耗时、从站状态、网卡链路与采集时间、ESC 计数及故障动作。每次故障保留前后各 5 秒周期片段；重复告警按状态变化及恢复记录，避免每个采样刷屏。诊断页可导出 ZIP。

后端重启会恢复近期本地事件摘要；展开时按唯一事件标识读取详情。新故障的前后各约 5 秒片段归入原故障，展示覆盖时段、显示样本数、时间缺口及周期／偏差／收发耗时／WKC 四图，支持滚轮和框选缩放。历史独立片段按原条目显示，不推测关联；采集中、未完成、无样本和加载失败分别提示，失败可重试。连续诊断时间线仍是当前进程的最近 30 分钟缓存。

管理页面可点“清空诊断日志”，在网页内确认框中取消或确认。确认后同时清空事件列表、本地 diagnostics 目录中应用管理的 events.jsonl 与 events-*.jsonl 及其中的故障片段。CSV、backend-shutdown.jsonl、配置、调试材料和连续诊断曲线保留；其他页面的旧详情请求会因日志代次变化而失效。清空结果只显示在界面，不生成新的清空操作日志。

ESC 低频读取 CRC/无效帧、物理接收错误、Lost Link、看门狗等寄存器。不可达或不支持标为未知；不自动清零，0xFF 饱和与设备重置单独标注。事件中设备不可达时，最近成功状态与新快照的采集时间用于区分历史信息。诊断 CoE 读取临时使用 2 ms 超时并在结束后恢复，AL 状态不可达时跳过 CoE；未知计数不写成零。新增读取耗时单独记录，不与 PDO 收发并发访问同一主站。[ESC 计数说明](https://download.beckhoff.com/download/document/io/ethercat-development-products/ethercat_esc_datasheet_sec1_technology_2i3.pdf)

可结合证据排查：链路实际断开且 Lost Link 增长，优先查电源与接触；特定端口 CRC/RX 持续增长，重点核对该段线缆、连接和干扰；WKC 无回应而链路及计数无变化，再检查收包超时、驱动和 Windows 调度。计数不增长不能排除硬件问题，不能把任何一项单独当作结论。

## 五、按层排查

1. **供电**：检查 EK1100 Us、极性、E-bus 与模块 LED。新环境按标称 24 V DC 配置。
2. **物理链路**：专用网卡直连 X1，核对 Up/100 Mbps、插头和线缆。拔插前按当前输出策略安排。
3. **Npcap**：安装 WinPcap API 兼容模式；管理员访问限制需相应启动权限。驱动不可用时页面给出具体错误。
4. **从站**：检查顺序、支持型号、实际 AL 状态、配置回读。拓扑变化后重新核对虚拟卡及校准，不换用其他网卡试图绕过检查。
5. **同步与 PDO**：确认滤波与同步组合受支持。DC/SM 要关闭输入滤波；参数回读失败不能强行上线。
6. **网页与 TCP**：管理页面失联不等于总线断开。刷新恢复后端状态；控制台按 O 重新打开网页。原版第二控制连接会被拒绝，扩展默认只读，写入还要对应通道权限。
7. **采集完整性**：原始队列缺口、慢客户端和协议积压分别记录。原版不能插入自定义报错帧，错误原因在网页及日志查询。

## 六、停止日志与快速复测

源码日志位于项目 logs，EXE 位于 %LOCALAPPDATA%\EtherCAT-Viewer\logs；结构化诊断在其 diagnostics 子目录。backend-shutdown.jsonl 保留 Ctrl+C/关窗退出与零值结果：confirmed 表示零目标获 WKC 确认，unknown 表示无法确认，not_connected 表示清理时已断开。

先网页清零并断开，再 Ctrl+C 或关闭控制台。独立长测会独占网卡，需先退出正常连接；命令见 [开发与发布](06-开发、打包与发布.md)。历史与本轮实测严格区分，见 [验收记录](05-现场现状与验收记录.md)。

## 七、参数未应用、回读不一致与页面恢复

“已保存”表示磁盘配置，“实际”来自通信进程或设备回读，“未应用草稿”表示还未提交。三者不相同不一定是通信掉线。参数回读不一致归入“模块与通道报警”；连接失败、运行异常、控制与配置事件各可筛选。

1. **输入后又变回旧值**：检查是否用了旧的页面资源，重新加载管理页。新版输入在失焦、切页和遥测推送后保留草稿；同字段外部修改会提示冲突，不会静默覆盖。
2. **点击应用被拒绝**：按字段错误检查范围、波形频率和设备能力；同步与滤波的关联项会列在按钮附近。不要通过整份配置覆盖来绕开校验。
3. **需要重配**：使用“清零并重连应用”，看顶部进度。结束后零值锁定属于预期；应重新授权，并由客户端发送新指令。失败保留草稿，不反复盲点。
4. **实际读取失败或未知**：日志明确区分“设备参数读取失败”“设备参数回读与配置不一致”和各自恢复。读取失败保留最后成功值及单调时间，不把空值当作真实参数参与比较；空异常文本会补充异常类型和中文原因。事件详情列出模块、通道、参数、期望值、实际值或失败原因。核对日志、WKC、AL 状态及回读额外耗时。回读任务和 PDO 共用主站，低频读取仍可能造成实际周期变长，应结合时间线判断。
5. **刷新后为只读**：同一标签页应恢复原管理会话；另一个管理页已经取得身份时，点击右上“本页只读”转移管理身份，原页面随即转为只读。这不自动转交 TCP 占用的 AO。
6. **网卡框为空或按钮卡住**：等待管理 WebSocket 恢复，再刷新网卡列表；选定只改变目标，点击连接才操作设备。当前连接不会因页面刷新而重建。请求超时后先查看后台状态，再重试。

事件中保留实际异常和证据；WKC 为 −1 说明没有收到本轮有效帧，不能据此单独判断是线缆、设备还是电脑接收超时。

模块页正常情况下不再重复列出“已保存／实际”数值行；参数回读失败或不一致时仍出现字段提示。启动开关有独立“保存中”状态，失败后恢复后台确认值并可重试；若显示“状态无法确认”，先恢复与服务的连接，再重试，避免把本地开关外观当作保存成功。通知历史的 ×、点外部关闭和 Esc 不改变总线连接或 AO 输出。
