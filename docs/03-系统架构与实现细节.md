# 三、系统架构与实现细节

## 一、完整技术路径

```text
浏览器六页管理界面（HTML / JavaScript / uPlot）
  ↕ 本机 HTTP / WebSocket · 127.0.0.1:8765
FastAPI（管理身份、配置、TCP 桥接、历史与日志、CSV、后台监督）
  ↕ 命令/结果队列 + 独立原始源队列 + 可丢弃网页队列 + 服务租约/清零事件
单个 spawn 通信进程（逐 AO 归属、波形、校准、容错、重连、DC 调度）
  ↕ PySOEM 1.1.13 / SOEM / Npcap · 二层 EtherCAT
EK1100 + 任意顺序和数量的 EL3104 / EL4134
```


公司软件连接原版 TCP 端口，扩展客户端连接扩展 v1 端口；两者都经现有通信进程操作物理模块。浏览器地址与 EtherCAT 二层接口是两段不同通信。网页、CSV、日志写盘、TCP 慢客户端不直接占用硬件循环。

| 模块 | 职责 |
| --- | --- |
| launch / console / system | 单文件入口、多进程分流、可见控制台、O 键、退出、当前用户登录启动 |
| server | 同源管理会话、命令协调、持久配置、监督、网页推送和 CSV |
| settings / calibration | 版本化原子保存、修订冲突、迁移、电气校准与工程量正反换算 |
| worker / generator | 唯一输出写入者、逐通道控制、波形、租约、容错与恢复 |
| hardware / pdo | 网卡、身份、CoE/PDO、同步与看门狗配置、真实状态和 ESC 计数 |
| bridge | 原版与扩展协议、每卡监听与权限、保持补点、缓冲及客户端生命周期 |
| diagnostics / timing | 30 分钟逐周期历史、峰谷抽取、10 秒统计、结构化事件和后台日志写入 |
| static | 六个导航页面、动态图表、配置编辑、术语注释与诊断曲线 |

## 二、设备身份、PDO 与通道

Windows 物理网卡与 Npcap 接口按 GUID 匹配。用户选定接口后显式点击连接；打开前重新检查接口和链路，并以 Windows 命名互斥锁防止本项目重复占用。生产程序没有模拟硬件连接入口。

主站要求第一个从站是 EK1100，后续只驱动 EL3104/EL4134；未知型号拒绝。逐模块读取 CoE PDO 分配 0x1C12/0x1C13，校验位偏移、长度、有符号表示和模块内缩放设置。WKC 预期值使用 SOEM 的实际映射结果。

真实通道 ID 由从站位置、型号和模块内通道组成，例如 s3:EL4134:AO1。拓扑指纹包含位置、厂商、产品与 Revision；模块增加、顺序或修订变化后需重新核对映射。完全相同身份模块互换无法仅凭指纹识别导线变化。无人值守及启用电气校准时，拓扑不匹配会阻止应用旧配置。

原始编码为有符号 INT16，−10 V→−32768、+10 V→32767。AI 先做量程换算再电气校准；AO 先由目标电压反算 DAC 指令，再检查可达范围并编码。清零和硬件替代值使用相同电气换算，跳过协议码值和工程量映射。厂商校准保持启用，软件校准不改写模块的用户校准系数。

## 三、循环、时钟与数据分发

目标周期 1–50 ms，默认 10 ms，使用 perf_counter_ns。迟到时跳过已经错过的调度槽，不突发补跑。输出波形按单调时钟逐周期生成；原版每张卡保留共享表更新时钟语义。周期切换先验证所有运行波形，拒绝时原任务不变。

支持能力回读后的自由运行、SM 帧同步和 DC；输入滤波在每片 EL3104 的 0x8000:06/15 配置并回读。DC 按支持的 SYNC 事件选取 1C32/1C33 模式，建立 DC 参考时钟和周期脉冲，主机调度使用相位误差及限幅积分校正。状态提供主机相位偏差和模块同步错误。主机发送/返回时间戳不等于 ADC 转换时刻或 DC 硬件时间戳。

当前已核对 EL3104 Revision 16–20 和 EL4134 Revision 1016–1021 的 DC 参数，按具体 Revision 选择 SYNC0 偏移与 SYNC1 延迟；未知 Revision 的 DC 配置拒绝应用。当前实物使用 SYNC1：EL3104 偏移 −100 μs、延迟 25 μs，EL4134 偏移 0、延迟 100 μs，来源为 [Beckhoff 官方 ESI](https://download.beckhoff.com/download/configuration-files/io/ethercat/xml-device-description/Beckhoff_EtherCAT_XML.zip)。进入 OP 前先用零 PDO 完成相位协调；运行时记录同步错误和丢事件计数。DC 修改周期由逐项应用流程清零、断开后重配，普通 SM 模式保留在线周期切换。

每轮记录发送起始与接收返回，约每 50 ms 向两条独立队列发布：原始源队列供 TCP 重采样；网页遥测队列允许丢弃并单独计数。浏览器切页只停止绘制，后端采集、TCP 与缓存继续。

原版保持策略按逻辑采样率重复有效前值，真实策略只选择新 PDO 样本。容错或映射通道报警期间暂停采集，重置保持段时间基准，不为缺口制造数据；已发生的源队列序号遗漏仍被判为中断。暂停时保留已完整组帧的数据，只丢弃不足一帧的片段；完整帧序号不能因容错被清空而无故跳变。

## 四、管理会话与逐通道输出归属

网页管理身份和 AO 写权限分离。会话令牌只在同源浏览器中使用，同一标签页通过 sessionStorage 恢复；旧 WebSocket 清理只移除它自己的队列，避免关闭旧连接误删新连接。命令使用独立 ID，重试去重有界缓存。第二页面默认只读，可显式切换管理身份。

后端服务独立续租，通信进程继续检查 2 秒服务租约。网页关闭默认继续运行；可按 AO 配置网页失联动作。TCP 每卡登记可写真实 AO、授权和连接令牌。网页可控制未转交的 AO；输入和只读输出映射可重复，真实 AO 的启用 TCP 写入映射必须唯一。

授权先对本卡可写 AO 送零并确认，再转交。TCP 控制端断开执行本卡失联策略，不影响其他卡；自动重新接管启用时，新连接先确认零输出。扩展显式 RELEASE 仍直接清零并要求重新授权。全局清零使用独立事件和代次撤销，停止所有发布，人工锁定不会被自动重新授权覆盖。

## 五、故障与生命周期

WKC 不匹配先进入 TOLERATING：记录异常，冻结最后确认目标，暂停采集，保留控制连接；连续 10 次或 500 ms 超限时执行逐 AO 总线策略。恢复时调整暂停的波形时钟，不追补缺口。明确退出 OP、链路断开、硬件异常直接执行故障策略。

总线策略支持归零、指定电压或保持；同时写入并回读 EL4134 看门狗替代行为。默认硬件看门狗 600 ms，至少比软件容错长 max(50 ms,2 个周期)。正常退出、人工清零与显式释放依旧请求物理零值；无法取得 WKC 时标明无法确认。

通信故障自动按 1/2/5/10/30 秒退避重连。恢复后检查拓扑、配置和零输出，稳定后恢复监听并等待新指令，不重放旧非零任务。工作进程意外退出由服务监督重建，旧命令撤销；服务失联由通信进程租约及模块硬件策略处理。人工断开取消连接意图。

## 六、持久配置与接口

统一配置在 %LOCALAPPDATA%\EtherCAT-Viewer\settings.json，版本 3，源码与 EXE 共用。包括硬件、故障策略、通道参数、启动设置、拓扑缓存和原版/扩展混合卡。修订号防止页面覆盖；临时文件 fsync 后替换，保留 settings.backup.json。旧 bridge.json 可迁移，卡 ID 保持。

| 接口 | 内容 |
| --- | --- |
| GET /api/status | 实机、健康、逐 AO 归属、操作进度、能力回读、统计与配置修订 |
| GET /api/adapters | 物理网卡及 Npcap 可访问性，可在连接时读取 |
| WS /ws?resume=令牌 | 恢复网页管理身份、接收状态及批量样本；令牌不进入日志 |
| POST /api/commands | 保留 id/action/args；preview_settings 规划单字段及关联项，apply_settings 应用经核对的列表；另有配置导入、逐通道控制、两点校准和逐卡启停 |
| GET /api/config | 版本化配置、真实配置与备份路径、登录启动状态、设备能力与参数回读 |
| GET /api/diagnostics/history | 指定时间范围及点数，返回保留峰谷/断点的周期历史 |
| GET /api/events | 分类事件列表，详细采样片段保存在日志与诊断包 |
| GET /api/diagnostics/export | 状态、历史和结构化日志 ZIP |
| GET /api/recording | 最近完成的 CSV |
| GET /api/bridge/network | 可绑定的本机 IPv4 地址 |

普通连接操作返回操作标识和进度；界面请求有超时，最终状态以后台推送为准。桥接报文完整布局、命令和兼容限制见 [第七篇](07-中瑞协议桥接与兼容说明.md)。

## 七、参数应用与回读的实现边界

参数逻辑由 viewer/configuration.py 负责纯计算：以字段路径为单位进行白名单校验和三方比较，将依赖变化列成明确的应用方案。路径中的虚拟卡使用稳定 ID，而非数组位置；禁止父字段与其子字段同时出现以免顺序覆盖。修订号用于整个文件的保存，字段原值用于识别真正的冲突，无关字段可以合并。

命令流程如下：

1. preview_settings 接收 changes，每项包含 path、base、value，返回 changes、related、reason、mode、noop 和 impacts。
2. apply_settings 接收相同 changes 与 approved。后端重新规划并核对整个批准列表；依赖已变化时拒绝执行，不能用旧预览跳过新的关联项。
3. live 通过通信进程的 runtime_config 完整校验候选配置后切换软件参数，波形保持相位；不满足新周期频率上限时拒绝，原任务保留。
4. reconnect 先触发全局清零代次，停止桥接、确认零值、断开，再配置并连接。人工清零可取消正在进行的应用。失败不保存新配置；回退失败的证据进入事件中心，不自动恢复旧输出任务。
5. 应用成功才原子保存。磁盘保存失败时尝试回退进程配置；任何无法确认的结果明确记录。相同配置不写盘、不建备份、不增加修订号。

配置版本 3 增加 modules 模块设置、startup.auto_connect，以及每张卡的 start_on_boot / authorize_on_boot。版本 2 的全局滤波和看门狗迁入实际模块；原无人值守意图迁为固定网卡连接及原启用卡的两项启动意图。保留稳定卡 ID、通道映射、校准和测量记录。旧全局字段仅作为迁移及无模块时的后备值，不作为重复 UI 入口。

设备参数约每 5 秒启动一批只读任务，由通信进程在 PDO 循环中串行执行，每轮至多读取一个字段，SDO 超时暂设 2 ms 并还原。输入滤波与替代策略字段各需读取两个对象，实际额外耗时单独记录；不是并发读取，也不是固定 5 秒完成承诺。回读覆盖同步模式、整片输入滤波、AO 模块看门狗和各路硬件替代行为；主站周期、超时及软件容错取通信进程当前已应用值。状态中的 parameter_readback 包含字段值、单调时间、耗时与错误。回读不修改配置、不触发新的输出命令。

viewer/static/drafts.js 管理字段基线、草稿与冲突；settings.js 负责参数控件及预览；bridge.js 管理稳定卡标签及按卡字段合并；ui.js 统一图标和通知。状态更新只刷新显示与未编辑字段，不整表重建。同源页面与静态资源要求浏览器重新校验，避免升级后继续运行旧的控制界面。

模块图片选择及卡内标签使用前端状态，按从站和通道稳定 ID 关联；不修改硬件配置或增加配置修订号。每张通道卡的校准方式、功能标签和输入 DOM 独立，切换时仅改变可见性。即时保存开关单独维护 pending 状态，直接构建单字段 base/value 请求，不进入 DraftStore 的 dirty 状态；失败后完成一次新的配置回读，区分未保存与响应丢失但已经保存。逐字段接口和配置版本保持不变。

网页管理入口合并到“本页只读”状态按钮，仍调用原 claim 命令；转移管理身份不触碰输出租约。通知历史采用原生 Popover 自动弹层，公共图标保留离线素材和第三方许可；所有图片仍随静态目录打包。
