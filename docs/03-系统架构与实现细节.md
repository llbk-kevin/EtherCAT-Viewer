# 三、系统架构与实现细节

## 一、技术路径

```text
浏览器（HTML / JavaScript / uPlot）
    ↕ HTTP + WebSocket · 127.0.0.1:8765
FastAPI / Uvicorn（控制权、遥测、CSV）
    ↕ 命令队列、结果队列、遥测队列、共享心跳
独立通信进程（周期调度、波形、输出保护）
    ↕ PySOEM / SOEM / Npcap · 二层以太网
EtherCAT 链路（EK1100 → EL3104 → EL4134）
```

应用以本机浏览器作为界面。静态资源随程序提供。Windows 使用独立的 `spawn` 进程运行通信循环，网页绘制与 CSV 写入由服务进程处理。主站与 EK1100 之间交换的是二层 EtherCAT 帧，浏览器的 HTTP 地址属于另一段通信。

| 组件 | 职责 |
| --- | --- |
| `launch.py` / `viewer/console.py` | 检查运行环境、监听端口、就绪后打开浏览器、控制台状态及退出日志 |
| `viewer/server.py` | 本机接口、控制权、WebSocket 遥测、CSV 和统计 |
| `viewer/worker.py` / `viewer/generator.py` | 通信进程、锁定保护、单调时钟波形、PDO 调度 |
| `viewer/hardware.py` / `viewer/pdo.py` | 枚举接口、SOEM 建链、从站身份与映射校验、量程换算 |
| `viewer/static/` | AO/AI 图表、操作表单、诊断和浏览器本地参考值 |

## 二、连接、设备映射和电压

Windows PowerShell 枚举物理以太网网卡，PySOEM 枚举 Npcap 可见接口，两者按 GUID 对齐。操作者选择接口，后台在打开前重验该接口、链路和 Npcap 可用性，并按 GUID 创建 Windows 互斥锁。

主站要求以 Beckhoff EK1100 开始，后续为受支持的 EL3104 / EL4134，允许多片及不同排列；其他型号拒绝连接。经 CoE 读取 `0x1C13`（输入分配）与 `0x1C12`（输出分配），从映射推导位偏移，检查缓冲区大小和字段。现场 EL3104 每通道 16 位状态加 16 位有符号电压，EL4134 每通道 16 位有符号输出。检查终端使用默认有符号表示、默认缩放与校准，并验证 AO 的看门狗零替代值。

从站先进入 SAFEOP，随后用零值过程数据和实际 WKC 确认 OP。输出编码使用有符号 16 位，负半幅按 32768、正半幅按 32767 缩放，所以 −10 V → −32768，+10 V → 32767。AI 按同一量程反算，状态位判定无效时用空值记录。AO 图显示收到 WKC 回执的量化指令，对实际端电压的独立测量见 [实机接线与仪表盘操作](02-实机接线与仪表盘操作.md)。

## 三、调度与数据流

- 目标通信周期为 1–50 ms 的整数，默认 10 ms。单调时钟为 `perf_counter_ns()`。迟到时跳过已过期的调度点，按后续时刻继续。
- 通信进程每周期计算各通道波形并调用 SOEM 收发。频率上限为 `min(100, 250 / 周期毫秒)` Hz。收到切周期命令时先检查运行波形；允许切换后按新间隔继续，波形由原单调时钟参考生成。
- 取相邻交换的发送起始差作为实际周期间隔，取发送开始至接收返回作为收发耗时。约每 50 ms 批量传给服务端，服务端按最近 10 秒计算统计。
- 浏览器批量接收样本，按共享时间窗画线，长时间窗保留峰谷和断点。显示刷新和通信周期独立；相关计数见 [通信诊断与故障排查](04-通信诊断与故障排查.md)。

## 四、本机接口、会话与保护

| 接口 | 用途 |
| --- | --- |
| `GET /`、`GET /static/…` | 仪表盘与资源 |
| `GET /api/status` | 当前实机、输出和时序状态 |
| `GET /api/adapters` | 网卡列表，包含 GUID、状态、速率及 Npcap 接口 |
| `WS /ws` | 建立页面令牌、接收状态和采样，服务端依据控制页心跳更新租约 |
| `POST /api/commands` | 同源会话提交 `{id, action, args}`；覆盖取得控制权、连接/断开、解锁、清零、直流、波形、停波、设周期和记录 |
| `GET /api/recording` | 下载最近结束的 CSV |

网页可同时查看。只有一个有效的控制会话可下发命令；服务端校验同源与会话令牌，通信进程使用代次和 2 秒租约校验归属。断线、WKC 失配、从站退出 OP、退出服务或控制会话失效时撤销非零输出。通信异常或退出时尝试送零并核对 WKC，再请求 INIT 并释放接口。每片 EL4134 SM2 的过程数据看门狗启用并回读，目标为 100 ms。重连后从零值、锁定状态开始。

## 五、中瑞协议桥接与动态通道

应用增加原版中瑞 TCP 和扩展 v1 TCP 两种入口。默认绑定回环地址，网页仍只在本机管理；TCP 可选择本机局域网 IPv4 并设置客户端白名单。协议语义和分帧以 [中瑞协议桥接与兼容说明](07-中瑞协议桥接与兼容说明.md) 为准。

真实通道目录由从站位置、型号和模块内通道组成；拓扑指纹包含位置、厂商、产品和 Revision。每片 EL3104 / EL4134 独立读取和校验四路 PDO，硬件层展平为动态 AI/AO 数组，预期 WKC 使用 SOEM 计算值。图表、模块筛选和 CSV 随真实通道数量生成。身份相同的模块对调不能依靠指纹识别导线变化，仍需现场核对。

viewer/bridge/ 分离配置校验与持久化、原版/扩展分帧、时间重采样和 TCP 生命周期。原始样本通过独立的有界进程队列分发，不经过网页的可丢弃队列或 CSV 写入路径。每个 TCP 连接使用串行有界发送队列，慢客户端不能阻塞主站。

通信进程是唯一真实输出写入者。网页模式使用原有页面租约；TCP 模式由服务独立续租，每张卡登记输出范围、授权和控制连接令牌。输出、波形、共享时钟及释放均在通信进程再次校验范围。全局清零使用独立事件优先处理，提升代次使旧命令失效；归零直接使用物理电压，绕过中瑞码值映射。

新增 GET /api/bridge/network 返回可绑定的本机 IPv4；POST /api/commands 增加 bridge_preset、bridge_save、bridge_start、bridge_authorize、bridge_stop 管理动作。状态增加 app_version、动态 channels、fingerprint、control_mode、源队列遗漏和 bridge 配置/运行统计；源样本增加 host_send_ns、host_return_ns。具体参数见第七篇及实现。

源码和 EXE 的桥接配置均保存到 %LOCALAPPDATA%\EtherCAT-Viewer\bridge.json，运行数据继续沿用原有路径策略。保存配置不表示恢复监听或非零输出。
