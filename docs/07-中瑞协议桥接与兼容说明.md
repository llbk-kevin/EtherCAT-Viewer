# 七、中瑞协议桥接与兼容说明

## 一、用途与支持范围

桥接程序把倍福 EL3104、EL4134 暴露为虚拟网络采集卡。公司软件作为 TCP 客户端连接桥接端口，单个 PySOEM 通信进程负责所有真实 PDO 交换。网页负责配置、监视、记录、授权与清零。

本功能自 v0.2.0 测试构建提供，v0.1.0 EXE 不包含桥接。真实中瑞板卡的协议事实见 [中瑞 E1682 TCP/IP 通信协议](../reference/中瑞E1682-TCP-IP通信协议.md)；本文规定本项目的兼容行为和自定义扩展，不改变外部参考文档。

| 项目 | 本轮实现 |
| --- | --- |
| 实机拓扑 | EK1100 后接任意数量、任意排列的 EL3104 / EL4134，至少一个 IO 模块；其他型号拒绝连接并说明原因 |
| 原版虚拟卡 | 每张固定 8 AI＋2 AO，不同卡使用不同端口 |
| 扩展虚拟卡 | 可配置 AI/AO 数量；AI 至少一个，AO 可以为零；受通道索引、报文及内存上限约束 |
| 电压与波形 | 原版 DAC 及任意表波形；可选双极性量程映射；扩展接口直接使用物理 ±10 V |
| 输入 | 单端、软件计算的差分、有限帧、连续采集；缺失输入明确补零 |
| 未配备的能力 | PWM、DIO 操作、硬件计数器、UART、外部触发和外部 ADC 时钟 |
| 验收边界 | 协议客户端与当前四输入四输出实机；公司软件代码未提供，其初始化行为及实际兼容性待联调 |

EL3104 的“差分输入”指每路正负端子的电气连接；原版命令 A113 则在桥接内计算虚拟通道之间的电压差，两者不能混为一谈。当前扩展协议版本为 1，与应用版本 0.2.0 分别管理。

## 二、网页配置与启动顺序

1. 在 EtherCAT 拓扑页选择专用网卡，再点击连接，核对拓扑、通道和 WKC，等待稳定。
2. 在中瑞桥接页点击虚拟卡列表右侧的 ＋，直接创建一张原版 8 AI＋2 AO 草稿，通道初始未映射。进入卡内可改为扩展，允许混合。复制默认只读，避免产生写入冲突。
3. 配置名称、IPv4、独立端口、允许访问网段、通道数、采样/缓冲、AI/AO 映射及逐 AO 读写权限。原版建议 6000 起、扩展 7000 起，8765 留给网页。扩展数量还受 1 MiB 帧和内存边界约束，保存时验证可编码。
4. 保存后逐卡或统一监听。只读卡可采集；可写卡需网页授权，原版连接即申请控制，扩展须另发 CLAIM。授权先确认本卡输出为零，再转交其可写 AO；网页可继续控制其他通道。
5. 公司软件同机连接 127.0.0.1:对应端口，跨机使用服务电脑局域网 IPv4 并加入允许列表。原版每卡一个控制连接，扩展每卡一个控制者、多个只读观察者。
6. 每卡可保存“允许客户端自动重新接管”，默认开启；第一次授权后，断开再连时先归零并接受新指令。扩展显式 RELEASE 属主动释放，仍清零并要求重新授权。
7. 停止本卡只清零其可写 AO，不影响其他卡和网页通道；全部清零并锁定则停止全部发布，并阻止自动重新授权覆盖人工锁定。

离线可使用上次拓扑编辑。加入模块、调整顺序或 Revision 改变后，实际发布需重新核对指纹和映射。输入可被多卡复用；AO 可重复做只读映射，但启用的 TCP 写入映射必须唯一。未映射 AI 固定零，mapped=false、valid=false；未映射或只读 AO 的写请求被拒绝并记录。

默认回环监听，可选本机局域网 IPv4；IP 白名单不提供加密或登录认证。跨机还受 Windows 防火墙影响。当前局域网测试包括本机访问自身 LAN 地址，第二台电脑另行验证。

版本 3 统一配置位于 %LOCALAPPDATA%\EtherCAT-Viewer\settings.json，源码与 EXE 共用；只接受当前格式，不读取旧 bridge.json。EtherCAT 拓扑页接口区域可启用固定网卡的冷启动自动连接，每张卡在配置底部的单行启动开关中独立设置监听和 TCP 写入：先检查拓扑与硬件、确认零输出，再接收新指令；不恢复旧非零任务。网页关闭默认后台继续运行，可独立配置网页失联行为。

## 三、原版协议与量程映射

### （一）兼容命令

原版帧使用 AA 55 帧头、单字节总长度、小端操作码、参数及 55 AA 帧尾。波形写入使用 FF 变长规则。拆包、粘包与带有帧头字节的波形数据均按已知长度解析；收到首字节后，剩余一条命令限时五秒，正常空闲连接不因此超时。

| 操作码 | 功能与参数 | 返回及限制 |
| --- | --- | --- |
| A111 | 八路，N:u32 | 1460 字节采集帧；N=0 连续 |
| A112 | 四路，G:u8 N:u32 | G=1 为 AI0–3，G=2 为 AI4–7 |
| A113 | 四路软件差分，N:u32 | AI1−AI0、AI3−AI2、AI5−AI4、AI7−AI6 |
| A114 | 两路，G:u8 N:u32 | G=1–4 |
| A115 | 单路，G:u8 N:u32 | G=1–8 对应 AI0–7 |
| A505 | 停止本连接采集 | 不停止独立 AO 波形；需排空已发送的完整帧 |
| A3E2 | RANGE:u8 SAVE:u8 | 1=±5 V，2=±10 V；只改变协议编码，真实 EL3104 仍为 ±10 V |
| A3D0 | DIV:u16 SAVE:u8 | DIV=650–65535，逻辑 Fs=130000000/DIV |
| A452 | 固定参数 13 A4 F1 C5 | 固定 46 字节设备信息 |
| A3D1 | X:u8 | FAF5 回复，Y=(X+1)&255 |
| A659 | CH:u8 CODE:u16 SAVE:u8 | CH=1/2/3 表示 AO1/AO2/两路，CODE=0–4095 |
| A65A | CH:u8 DIV:u16 LEN:u8 CODE:u16[LEN+1] | 总长度 11+2×点数，长度字节 FF；每路 1–256 点 |
| A65B | NC:u8 DIV:u16 | 总长度必须为 10 字节，建议 NC=55；更改该卡全部表波形的共享时钟 |

SAVE=1 即时，SAVE=2 保存。量程和采样分频保存到该虚拟卡配置，设备信息返回其保存值；采集期间改变这些参数会被拒绝。非零上电 AO 保存不支持，重启和重连始终从物理零值开始。

A452 沿用参考文档的字节偏移：17–20 为虚拟监听 IP，21–22 为端口，23–26 网关置零，27–30 为虚拟掩码，31–36 为由虚拟卡 ID 确定的本地管理 MAC。身份模板为 ID=26 20 00 14、硬件=23 45 00 00、固件=6D 12 03 0D。这些是兼容身份，不表示实际装有对应中瑞固件。运行次数填 1，保留区填零。

网络/MAC/身份写入、软重启、触发、外部时钟及数字等未实现命令，会记录原因并关闭控制连接，按该卡对应真实 AO 的 TCP 失联策略处理（默认清零）。已支持命令的无效参数则拒绝执行，在网页记录原因，保留连接与原输出。原版无统一错误回复，因此不额外插入自定义 ACK；如需可编程错误结果，使用扩展协议。

### （二）采集帧

| 字节偏移 | 内容 |
| --- | --- |
| 0–1 | AA AA |
| 2、3 | DI、DO，均为零，表示本版本未提供此硬件能力 |
| 4–11 | 两个计数器位置，均为零 |
| 12–15 | u32 小端帧序号，每次采集从 1 开始，按 32 位回绕 |
| 16–1455 | 720 个 i16 小端 ADC 值，按时刻交织 |
| 1456–1459 | 保留，零 |

每通道每帧样本数为 720/通道数：八路 90、四路 180、两路 360、单路 720。N 表示完整帧数。电压为 raw×FS/32768；编码时先按当前虚拟量程换算，再限制到 −32768…32767。虚拟 ±5 V 档超过范围会截幅，扩展状态提供 clipped 标记；真实硬件状态无效则暂停相关采集，不把故障伪装成零值；恢复后从新有效源继续。

完整示例：

- 八路采三帧：AA 55 0B 11 A1 03 00 00 00 55 AA。
- 四路低组连续：AA 55 0C 12 A1 01 00 00 00 00 55 AA。
- 2 kS/s 即时设置：AA 55 0A D0 A3 E8 FD 01 55 AA。
- 停止：AA 55 07 05 A5 55 AA。
- 回显：AA 55 08 D1 A3 7F 55 AA；回复 AA 55 08 F5 FA 80 55 AA。

### （三）AO 量程与波形

| 策略 | 从旧软件数值到物理目标电压 |
| --- | --- |
| 保持原量程，默认 | V=3.3×CODE/4095 |
| 双极性映射，可选 | V=20×CODE/4095−10 |

双极性映射会把旧软件的 0 V 指令变为物理 −10 V，把 3.3 V 指令变为物理 +10 V。CODE=2047/2048 分别约为 −2.442/+2.442 mV；12 位码不能精确表示物理中点。旧软件若用 CODE=0 停波，物理输出将到 −10 V，不能把它视为安全清零。

人工清零、主动停止与正常退出绕过此映射，发送对应物理零目标；异常断开按已保存的逐 AO 策略处理。所有电气目标经过统一 AO 电气校准反算。网页 AO 曲线与 CSV 显示获 PDO 回执的量化物理目标，不等同于独立电压测量；桥接区另列旧软件码值及其换算目标。

表波形更新率为 130000000/DIV，周期频率为更新率/点数。同一卡共用时钟，不同卡可分别配置。通信进程按单调时钟取表，不按 TCP 到包时刻逐点输出。周期目标保持 1–50 ms，表波形频率上限沿用 min(100,250/周期毫秒) Hz；恒定表按直流处理。少于 20 次实际更新/波形周期时提示明显台阶。

示例：DIV=65000、256 点时约 7.8125 Hz；10 ms 目标周期只有约 12.8 次更新/波形周期。高于输出频率上限的表或时钟变更被拒绝，不悄悄降速，也不替换原输出。切换主站周期不重置波形时间参考。

## 四、采样策略、延迟与数据质量

| 策略 | 数据含义与适用情况 |
| --- | --- |
| hold，兼容保持 | 生成请求节拍的逻辑数据；相邻有效 PDO 样本之间保持前值，不插值。适合保留旧软件既有采样配置 |
| native，真实采样 | 每个点选自一次新 PDO 交换，不补点；可降低取样频率，请求高于目标 PDO 更新率时拒绝 |

默认 10 ms 约对应每秒 100 组 PDO 输入，200 kS/s 兼容流不能视为 200,000 次独立测量。原版分频字段定义的最低速率约 1983.67 Hz，而当前程序 1 ms 目标也只有 1000 组/秒，因此当前硬件路径的原版 native 采集会拒绝正常高采样请求；低速、不补点及准确的到达时间信息应使用扩展接口。

原始队列与网页推送、CSV 写入独立。原始样本每约 50 ms 批量分发，网页跳帧只影响网页；源样本序号缺口或过期会结束受影响采集；已识别的 WKC 容错及通道报警则暂停、恢复后重建保持段，不补发缺口数据。超过一秒的源队列积压触发通信故障策略。相邻源数据时间中断大于 max(100 ms,三个目标周期) 也会停止该采集。

发送批量可调 5–1000 ms，默认 50 ms。实际推送还受源批量、完整帧填充及系统调度限制；八路原版在 2 kS/s 时一帧需 45 ms，单路需 360 ms。此设置不是硬实时延迟承诺。

source诊断在失效或源过期时设置live=false，实时WKC与最新耗时为空，last_wkc及累计异常用于追溯；所有TCP诊断均可独立于网页读取。

积压上限默认 2 秒，可调 0.1–10 秒；单连接还有 8 MiB 内存限制；单个源时间段展开后的ADC数据限制为512 KiB，超出时需降低逻辑速率或通道数量。发送超时或积压超限只关闭对应连接，控制连接关闭后清零该卡。该上限约束桥接的发送等待，不能测出客户端收到后又缓存了多久。

扩展和网页分别显示请求逻辑速率、真实源数据率、源样本数量、保持补点数、截幅、发送积压和缓冲延迟。调度漏期、源队列遗漏、网页推送遗漏与 TCP 帧序号缺口分别统计。

## 五、扩展 v1 报文与命令

### （一）统一封装

扩展端口与原版端口独立，所有扩展报文采用同一种封装：

| 偏移 | 字段 |
| --- | --- |
| 0–1 | AA 55 |
| 2 | FF |
| 3–4 | 操作码，u16 小端 |
| 5–8 | L，u32 小端；表示版本字节及消息体的总长度，1–1048576 |
| 9 | 协议版本，固定 01 |
| 10 至 8+L | 消息体 |
| 9+L 至 10+L | 55 AA |

总长度为 11+L 字节。一个接收调用可能只返回部分报文，也可能包含多条报文；按显式长度读取，不能依赖 TCP 包边界或在二进制数据中搜索帧尾。

控制请求的消息体是 UTF-8 JSON 对象，可附 id。回复为同一操作码和对象 {"id":...,"ok":true,"result":...}；错误操作码 E1FF，包含 id、ok=false、error。不要假定发出请求后下一条就是回复，连接中还可能有采集数据或事件。

连接后服务端主动发送 E100 能力报文，包含 version=1、该卡配置、真实通道、目标周期、支持/不支持能力及报文上限。

能力查询 id=1 的完整报文：

AA 55 FF 00 E1 09 00 00 00 01 7B 22 69 64 22 3A 31 7D 55 AA

### （二）命令索引

扩展 AI 索引从 0 开始，AO 编号从 1 开始，与原版两者习惯一致。

| 操作码 | 功能 | JSON 参数与含义 |
| --- | --- | --- |
| E100 | 能力查询 | id 可选 |
| E101 | 申请该卡控制权 | 须已获网页授权且无控制者 |
| E102 | 释放控制权 | 清零本卡并锁定，停止本连接采集；再次申请需网页授权 |
| E110 | 开始本连接采集 | channels:AI索引数组，默认全部；rate_hz:1–200000，默认100；range:1或2，默认2；blocks:0连续或正整数数据块数 |
| E111 | 停止本连接采集 | 不改变独立 AO 输出 |
| E120 | 直流输出 | channels:AO编号数组，volts:对应物理电压数组，范围 ±10 V；需控制权，原子校验 |
| E121 | 任意表波形 | channel:AO编号，volts:1–65536个物理电压，rate_hz:表更新率；需控制权 |
| E122 | 修改表更新率 | rate_hz，作用于该卡所有表波形，保持相位；需控制权 |
| E130 | 桥接状态查询 | 各卡状态、连接、统计、最近错误；source字段给出OP状态、目标周期、WKC、看门狗、异常/漏期/源遗漏、最新间隔及收发耗时 |
| E131 | 订阅状态事件 | enabled:true/false，默认true；启用后约每250 ms推送 E1F1 |
| E1F0 | 采集数据，服务端推送 | 下述二进制消息体 |
| E1F1 | 状态事件，服务端推送 | JSON 状态 |
| E1FF | 命令错误，服务端回复 | id、ok=false、error |

E121/E122 更新率须为有限正数，最高 13,000,000 点/秒，同时满足实际波形频率限制；逻辑表点率不等于物理更新率。新增表会统一应用该卡的共享时钟，单独修改时钟则保持既有表的相位。

blocks 表示扩展数据块数量，不是原版 1460 字节帧数，也不是样本数；使用连续模式并按 sample_count 累计，可取得所需逻辑样本数。

### （三）采集消息体

E1F0 的消息体先放 4 字节 u32 小端元数据长度 M，再放 M 字节 UTF-8 JSON，最后放交织的 i16 小端 ADC 数据。版本字节属于外层，不计入此消息体。

| 元数据 | 含义 |
| --- | --- |
| sequence | 本连接本次采集的数据块序号，从1开始 |
| channels、channel_count | 虚拟 AI 索引及其数量 |
| sample_count、encoding | 本块采样时刻数量；encoding 固定 i16le |
| full_scale | 当前协议满量程5或10；电压=raw×full_scale/32768 |
| sampling | hold 或 native |
| logical_start_ns、logical_interval_ns | 本块逻辑时间起点及名义间隔 |
| source_seq、source_session | 对应原始 PDO 样本序号及实机连接代次 |
| host_send_ns、host_return_ns | 该源样本的主机 PDO 发送起点及接收返回时刻 |
| timestamp_source | 固定 host_pdo_exchange，不是硬件 ADC/DC 时间戳 |
| valid、mapped、clipped | 每通道有效性、是否映射及虚拟量程截幅标志 |
| held_count | 本块保持补点数量；hold 段通常为 sample_count−1，native 为0 |
| source_interval_ms | 相邻源 PDO 交换起始间隔 |

二进制数据长度必须为 sample_count×channel_count×2。hold 块内使用同一源样本，重复的逻辑点共用 source_seq 和源时间戳；native 块只包含一个新取得的源采样时刻，读取真实时间应使用 host_send_ns。跨连接不能比较 sequence，跨后端重启不能直接拼接单调时钟时间。

## 六、控制权与异常恢复

- 网页管理与 AO 写权限分离，网页刷新不改变后台任务。网页与 TCP 按真实 AO 并行，每路只有一个写入者。
- 读写权限、连接令牌和输出范围在服务端及通信进程再次校验；同卡多路写入先整体验证，拒绝时保留原输出。
- 控制连接异常退出按 TCP 失联策略停止波形并归零、保持或设定电压，默认归零；其他卡不受影响。只读连接退出不改变输出。
- 默认 WKC 连续 10 次或 500 ms 才进入故障处理，容错期间暂停采集、冻结末值，保留连接。明确断链/退出 OP 立即处理。总线策略同时配置模块硬件看门狗，默认 600 ms。
- 超限撤销旧写入者并结束其连接；扩展只读可继续看状态，采集结束。自动重连重新确认拓扑、零输出和稳定通信后恢复服务，等待新指令，不重放旧波形。
- 后端租约始终有效性检查，网页默认可关闭而保持后台运行。服务进程异常由通信进程和硬件策略兜底。
- 全局清零优先于排队命令，提升代次、停止监听并锁定，自动重连授权不会自动解除人工锁定。正常退出仍清零、INIT、释放网卡，未确认时日志记录 unknown。

扩展 DATA 保留 v1 帧布局，新增可选 engineering（对应通道的工程量值）和 channel_profiles（名称、校准及单位映射元数据）。电压编码仍用校准后电压，原版不引入物理量单位或自定义错误帧。新客户端可读取新增字段，旧客户端可忽略。

## 七、最小 Python 客户端

以下示例仅依赖 Python 标准库，在扩展卡已开始监听后读取两个数据块，不申请输出控制权。根据配置修改 HOST、PORT。

~~~python
import json
import socket
import struct

HOST, PORT = "127.0.0.1", 7000

def receive_exact(sock, size):
    result = bytearray()
    while len(result) < size:
        data = sock.recv(size-len(result))
        if not data:
            raise ConnectionError("服务端断开")
        result.extend(data)
    return bytes(result)

def receive(sock):
    head = receive_exact(sock, 9)
    if head[:3] != bytes.fromhex("AA55FF"):
        raise ValueError("帧头错误")
    opcode, size = struct.unpack_from("<HI", head, 3)
    if not 1 <= size <= 1048576:
        raise ValueError("长度无效")
    body = receive_exact(sock, size+2)
    if body[0] != 1 or body[-2:] != bytes.fromhex("55AA"):
        raise ValueError("版本或帧尾错误")
    return opcode, body[1:-2]

def send(sock, opcode, value):
    body = b"\x01" + json.dumps(value, separators=(",", ":"), allow_nan=False).encode()
    sock.sendall(bytes.fromhex("AA55FF") + struct.pack("<HI", opcode, len(body))
                 + body + bytes.fromhex("55AA"))

with socket.create_connection((HOST, PORT), timeout=5) as sock:
    sock.settimeout(5)
    opcode, hello = receive(sock)
    print("能力", json.loads(hello))
    send(sock, 0xE110, {"id": 1, "channels": [0], "rate_hz": 50, "blocks": 2})
    count = 0
    while count < 2:
        opcode, body = receive(sock)
        if opcode == 0xE1FF:
            raise RuntimeError(json.loads(body))
        if opcode != 0xE1F0:
            print("回复", json.loads(body))
            continue
        metadata_size = struct.unpack_from("<I", body)[0]
        metadata = json.loads(body[4:4+metadata_size])
        data = body[4+metadata_size:]
        expected = metadata["sample_count"] * metadata["channel_count"] * 2
        if len(data) != expected:
            raise ValueError("数据长度与元数据不符")
        raw = struct.unpack("<" + "h" * (len(data)//2), data)
        volts = [v*metadata["full_scale"]/32768 for v in raw]
        print(metadata, volts)
        count += 1
~~~

## 九、卡片草稿与逐卡冷启动

虚拟卡使用带中瑞实物缩略图的横向卡片标签展示，每张卡的配置草稿独立，按稳定 ID 管理。点击 ＋ 追加原版草稿，不替换已有卡；复制生成新 ID、空闲端口和只读 AO，不复制启动写授权。删除当前卡后选相邻卡；缩减通道或改原版时会提示移除的映射。监听中的卡需要先停止再修改结构。

保存卡配置时按卡字段三方合并。例如编辑名称期间另一个入口改变了该卡的启动选项，保存名称不会覆盖启动选项；同字段冲突被拒绝，草稿保留。启动开关单独即时保存，不夹带卡片结构草稿。

固定网卡自动连接设于 EtherCAT 拓扑页接口区域；每张已保存卡的两枚启动开关直接展示、无需展开，分别设置监听和 TCP 写入。仅胶囊本体或键盘操作会修改开关；即时保存状态与整卡结构草稿分开。两项不是当前运行启停按钮，也不立即授权输出。完整冷启动链条要求打开固定网卡自动连接，并通过保存拓扑、硬件参数和零值检查；随后只发布勾选监听且启用的卡，再授权其中允许启动写入的卡。某张卡监听失败独立记录，人工全局清零仍优先撤销自动意图。若未开启固定网卡自动连接，启动保持等待，不自动挑选另一张网卡。

每卡运行详情显示逻辑采样率、有效采集源速率、保持补点、队列和延迟，避免把补点速率当作物理采样能力。原版报文字节与扩展 v1 语义保持原定义，本轮 UI 重排不更改真实中瑞板卡的外部参考协议。
